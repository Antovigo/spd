# Objective 1: find best hyperparameters

There are currently three running runs: sched-rel, sched-hi and sched-lo. This is to test whether release the impmin coefficient helps with the decomposition. The first objective is then to analyze the results from these tests to determine whether scheduling the impmin coefficinet works and what dynamics work best. The most important metrics for success here are: 1) the number of alive components at the end of training (n_alive) and 2) the reconstruction accuracy, both the rounded version and (most importantly) the PGD version. If the impmin-scheduling works as expected, it should have a better reconstruction accuracy than sched-hi, while also having a lower n_alive and total L0 than sched-hi. Now, the question is whether it does better than the midpoint between the two.
It is also possible that we released the impmin coefficient too much, so the decomposition reached an optimal state earlier during training, but then many more subcomponents started to activate as we released the impmin coeff further.
So, to test whether this trick works, we need to look at all the eval checkpoints throughout impmin annealing, and check whether *any* of these checkpoints is better (or not significantly worse) than both sched-lo and sched-hi as their final checkpoint. If it is, then impmin scheduling works — for the rest of the experiments, we use impmin scheduling with a final value for the impmin coefficient equal to what it was at the optimal checkpoint.
If there’s no evidence that impmin scheduling works: then, look at sched-hi’s final rounded reconstruction accuracy. If it’s below 0.005, we can use the coefficient’s high value throughout. If it’s above 0.005, then we check the final L0 for sched-lo: if it is below 7, then we use the coefficient’s low value throughout. Otherwise, stop here and I’ll have a look.

# Objective 2: decompose multiple layers at the same time

Consider the best decomposition on addition for layer 18’s MLP, and for layer 18’s attention. Look at how many alive subcomponents they have in total. For decomposing the rest of the network, we will use values of C equal to 2 times the number of alive subcomponents found in the best decompositions for layer 18. (That is, we use the same value for C for all attention layers, and the same other value for C for all MLP layers).
Now, the goal is to run the decomposition for as many layers as possible. Start with layer 18, then add 17, then add 19, then add 16, and so on. Add layers until the decomposition no longer fits on 4 GPUs. Once you have figured out the maximum number of layers that can be decomposed at the same time in this way, make a serious run using the best hyperparameters used so far (including what you’ve learned from Objective 1).
