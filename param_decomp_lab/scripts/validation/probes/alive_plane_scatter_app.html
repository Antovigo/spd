Residual stream on the probe planes — real vs. alive-only circuits

Each point is one prompt at the = token. view picks the layout: all layers columns are stream positions — block outputs (after N) interleaved with post-attention states (attn N) — for one chosen period; all periods columns are periods instead, for one chosen layer. Rows 1–2: the stream projected on that layer's own probes for a and b — the data each block works with. Row 3: the result probe fixed to one picked layer (probe layer, default final), evaluated at whichever stream layer each column implies. data picks which source is shown: the real model, or a circuit with only output-alive (or, on a dual-CI checkpoint, only hidden-alive) components active (delta off, everything else hard zero — the same masking `find_alive_subcomponents` uses). Every source is captured over the exact same sampled points, so they're directly comparable. distortion colours by each point's plane-projected distance from the real model (meaningless — and disabled — while viewing the real model itself). causal importance colours every panel by one selected alive subcomponent's CI on that prompt (read from the real model, so it doesn't depend on which source is shown). The Δ-from-previous-position colour modes and displacement arrows only make sense across stream positions, so they're disabled in the all-periods view. component arrows overlays each alive subcomponent's own direction on the plane, drawn from the origin as the displacement it contributes: U shows the components that write to the stream, V those that read from it (read directions include their RMSNorm gain). Each arrow appears only in the column whose stream position that component actually touches — a layer-ℓ down_proj write at after ℓ, a gate/up read at attn ℓ, a q/k/v read at after ℓ−1 — so most columns stay empty for a single-layer decomposition. min |proj| hides arrows whose in-plane length is below the threshold; length scales every arrow by a common factor (relative lengths are preserved, so arrows stay comparable). Hover an arrowhead for the subcomponent's name, in-plane length, and angle to the plane (0° = it lies in the plane, 90° = orthogonal to it). frame sets what the origin means. activation plane (default) projects onto the probe plane's orthonormal basis and drops the probe bias, so the origin is the true activation-space zero: a ring that is off-centre here is genuinely off-centre in the model. This is the frame the arrows mean something in — the target model has no biases, so a component's read x·V vanishes on a hyperplane through that zero (RMSNorm rescales but never recentres), and the angle an arrow makes with a point is the real in-plane angle between the activation and that component's direction. probe prediction plots the probe's predicted (cos, sin) instead: its origin is the mean activation, and its axes are skewed, because w_cos and w_sin are neither orthogonal nor equal-norm — so angles there are not in-plane angles. It keeps the ring near unit radius (dashed circle) and is the better view for judging probe fit. Both are computed from the same shipped data, so switching is instant. Dashed lines mark each panel's zero; tick labels give the axes' scale and sign. Panels default to centred on the origin, sized to fit the real model's own cloud (with slack) — reproducible across separate renderings of this applet on the same base model and probes, regardless of which source is currently shown. Scroll to zoom toward the cursor, drag to pan, double-click to reset — one row's panels share a frame, so zooming any of them zooms the whole row.
