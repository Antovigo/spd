Integer representations — how to read this applet

Decomposition p-ba5a0c05 step 40000. The read basis at a read point is the span of the input vectors V of the CI filter's alive components that read the residual there (q/k/v at attn_in.l, gate/up at mlp_in.l); k is its dimension. Every number is about the residual projected on that basis. Method: notes/arith_representations/plan.md; findings: report_representations.md.

Hypotheses (columns)

A hypothesis is a subspace of functions of the prompt. Q:tau = the pure period-tau code of quantity Q (functions of Q mod tau orthogonal to every coarser period and to the linear part; periods = divisors of 100). Q:lin = the linear (magnitude) part. Q:direct = the non-periodic remainder (only when the range exceeds 100). Quantities: a, b, op, and the results a+b / a-b — the one the operation asks for is the result, the other is a negative control (on the pooled set the result is a+b|a-b, i.e. a+b on addition prompts and a-b on subtraction prompts, and the control is a-b|a+b). Result hypotheses are interaction-only (orthogonal to every function of a alone and of b alone), so a linear result code is credited to a:lin + b:lin. Q:100 is token identity for the operands and cannot generalise by construction. Columns are drawn per position only for hypotheses fitted there; a quantity is only sought once its tokens are visible (0 BOS, 1 a, 2 op, 3 b, 4 =).

read points

Show every read point, only the MLP inputs (mlp_in.l, k ≈ 80–360 reads: the informative rows for separability) or only the attention inputs (attn_in.l, k ≈ 7–76).

ops

add / sub: fits on one operation's prompts (subtraction only a ≥ b). both: pooled; b becomes the op-conditional b@add/b@sub, the result is a+b|a-b (a+b on addition prompts, a-b on subtraction prompts), op:2 exists. Positions 0–1 precede the operator, so only the pooled fit exists there and is shown under every setting.

score (cell colour)

  • generalising energy — fraction of the read-basis energy at (read point, position) carried by the fitted directions that predict prompts whose a or b value was held out (5 folds, 20 % of values each), above the 99.9th percentile of a label-permutation null. The presence score.
  • unique energy — energy lost when this hypothesis is dropped from the joint fit; the conservative number when hypotheses overlap (subtraction, pooled set).
  • marginal energy — the raw fit, generalising or not (token identity shows up here).
  • dim S_H — number of kept (generalising) directions: 2 = one Fourier pair / circle, 4 = both harmonics of mod 5 or mod 10.

max sets colour saturation; log colour for the 0.5–2 % codes; the energy filter hides columns that never reach that generalising energy. Grey cells are hypotheses that were fitted but have no generalising direction there (the code is absent); they are not clickable. Blank cells were not fitted at that position.

Detail panel (click a cell)

Header: outside read basis = share of ‖x‖² the alive reads cannot see; joint = share explained by all hypotheses; kept = by generalising directions only; the null R² threshold. Hypotheses table: dim H (hypothesis dimension), marginal/unique/generalising energy, dim S, #reads (alive components reading it above the null), held-out R² of the top directions. Separability: green = some alive read lands in the row subspace at the 99.9th percentile of the random-direction null while sitting at that null on the column subspace, and vice versa; red = not separable. Per-kind clusters below. A hypothesis no component reads is unread and left out of the graph. Caution: at attention read points (k ≤ ~60) the null is nearly degenerate and most hypotheses come out unread — a limit of the null, not evidence. add vs sub cosines: principal cosines between the subspaces fitted on each operation (≈1 = same code). Clusters: connected components of “not separable”, with the union dimension and the singular values of the stacked class centroids (two equal values then a drop = one plane).

3-D view

Pick a value and a period (only codes with at least one generalising direction; absent codes are the grey cells of the map and cannot be selected). show chooses what a class centroid is: the full residue centroid (raw mean activation of the class — for a+b mod 20 this contains the whole mod-10 structure, so residues r and r+10 nearly coincide when the period-20 part is weak), or the pure-part centroid (the class mean of the pure part's fitted signal: what is left once every coarser period, the linear part and the mean are removed — the object the energies, clusters and separability are about; it is centred, so the origin is then the mean activation; overlaid hypotheses are shown as their own pure parts). The class centroids of that code (one per residue, or per value for lin/direct; label = class; hsv colour by class when it is the only code displayed, one colour per code otherwise; line joins consecutive classes) are shown on the top-3 principal components of the code's full residue centroids (PCA of the class centroids, prompt-count weighted). That span also contains every coarser period, the linear part and centroid noise — a mod-10 code has up to 9 non-zero bars in the spectrum although its pure part is 4-dimensional. The origin (small ×) is the zero of the post-RMSNorm residual in read coordinates — the reads have no bias, so it is the reference the model uses; the PCA axes are taken about the prompt-mean activation while the coordinates are not re-centred; the bar chart above is the centroid spectrum, so you can see how much of the code's centroid energy the three axes miss. Other hypotheses can be overlaid (collapsible list, none on by default; the cluster mates — those not linearly separable from the selected code by the alive reads — are marked): their centroids are projected on the same axes and do not influence them, which shows how much they would leak into a readout along these directions. Component arrows: every alive read of this read point's kinds (colour = matrix: blue q/gate, green k, orange v/up), drawn from the origin as the projection of its unit read vector into the displayed 3-D space, scaled by the cloud radius — so an arrow reaching the cloud is a component whose read direction lies entirely in these three PCs, and its direction is literally where it reads. The slider hides arrows shorter than a minimum projected length. Hover/click also report the overlap (‖P_S V_c‖/‖V_c‖) and first principal angle with the code's subspace, which is a different question — which subspace matters: by default the pure part's kept directions S_H — what the code means everywhere else in the applet (functions of Q mod τ orthogonal to every coarser period and to the linear part, restricted to the generalising directions); alternatively all fitted directions of the pure part, or the span of the full class centroids, which is much more inclusive (it contains every coarser period, the linear part and the mean, so a component reading b mod 10 overlaps the b mod 50 centroid span almost fully) — a component reading the code fully reaches the cloud, an orthogonal one has zero length. Click an arrow tip for the matrix, the component index, the projected length and the overlap/angle.
